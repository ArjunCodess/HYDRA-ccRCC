# Revision artifact sources and regeneration boundaries

This is a source-code dependency map, verified on **2026-10-01**. It identifies what each stage reads and writes; it does **not** attest that a stage has completed in the current run. Completion and exit statuses come from `results/tables/revision_command_log.csv` and the final validation record. An unchanged file can be regenerated, and a changed file is not by itself proof of a successful scientific analysis.

`run_pipeline.ps1 -SkipInstall` orchestrates the cached-input analysis. It records individual step exit statuses and stops at the first nonzero status. `build_paper.ps1` is a separate manuscript build. `analysis/41_review_claim_audit.py` validates manuscript claims. `analysis/42_review_artifact_manifest.py` expands this verified map into a machine-readable producer inventory and checks that maintained results have source coverage. Fresh retrieval with `-ForceDownload` is different from reproduction using the frozen inputs.

## Input identity, versions, randomness, and dates

The public-input inventory is `results/tables/input_manifest.csv`: a row per file, with its path, byte count, and MD5. `analysis/00_verify_inputs.R` verifies the inventory before the analysis; `analysis/18_write_manifest.R` inventories the inputs and generated outputs at the end. `results/tables/run_manifest.csv` records output and source-code MD5 hashes. `environment/package_versions.csv` is the version lock, `analysis/00_check_environment.R` requires R 4.6.1 and verifies the installed packages, and `environment/sessionInfo.txt` records the runtime. The new review figures also write `environment/review_figures_sessionInfo.txt` and `results/tables/review_figure_sources.csv`.

Original cached-input retrieval dates were not recorded. The 2026-10-01 verification date is **not** an original access date. `results/tables/source_provenance.csv` leaves access dates missing and states the cached-input limitation. TRACERx files use repository commit `3fefd80afe33cafc091b3154dbd32d8c27b92c81`; the CheckMate workbook checksum is specified in `analysis/00_config.R`. Local gene annotation is supplied by the locked R/Bioconductor packages, not by an unrecorded live lookup during every analysis.

All R analysis stages source `analysis/00_config.R`, whose default seed is 20260530. Stochastic stages override it as follows, with `RESAMPLING$seed = 20260725`:

| Stage | Seed specification and what is resampled |
|---|---|
| 11 | 20260530; permutation of survival-filter labels within reproducible DEGs, not refitting survival models. |
| 15 and 16 | `RESAMPLING$seed + 1`; fixed-candidate coefficient bootstrap and repeated conditional clinical-increment evaluation. |
| 20 | `RESAMPLING$seed + 20`; TRACERx patient/region scenarios. |
| 22 | `RESAMPLING$seed + 22 + repeat_id` for folds, `+23` for patient bootstrap, `+24` for the clinical null. The initial stage seed is `+22`. |
| 24 | `RESAMPLING$seed + 25`; paired bootstrap comparison of external procedure results. |
| 31 | `RESAMPLING$seed + 22 + repeat_id` for patient splits; patient-bootstrap seed is `RESAMPLING$seed + 31`; additional seeds are passed through the benchmark helper. |
| 32 | The shared fold seed above; `RESAMPLING$seed + 32` for signature uncertainty. |
| 33 | `RESAMPLING$seed + 33`; survival-outcome permutation sensitivity. |
| 39–41 | No analysis resampling; joins, plots, and manuscript validation use recorded results. Stage 40 uses seed 1 only to jitter benchmark display points. |

Stages 22 and 31 can reuse fold checkpoints. Stage 22 compares MD5 signatures of its script, configuration, patient-sample helper, TCGA SummarizedExperiment and clinical file, and the two GEO DE tables. Stage 31 adds its benchmark helper and records the screen size, seed, and ridge specification in the checkpoint specification. A reused, matching checkpoint is a cached analysis result, not a newly refitted fold; the pipeline logs say which checkpoints were reused. Stage 33 reads the first-repeat stage-22 fold caches. These boundaries should remain explicit when describing regeneration.

Stage 44 permits a narrowly verified benchmark-cache migration before stage 31: it compares parsed code against recorded historical source versions, allowing only the plot basename, comments, an unused aliquot helper, the added inner-fold validity guard for already successful ridge fits, and replay of the primary fold's recorded outlier-replacement policy. Configuration, frozen data, seed, screen size, and ridge specification must match. Clinical and HYDRA predictions, outcomes, patient identities, and selected genes and replacement settings must agree with newly refitted current-signature primary folds. Original checkpoint files/specifications are backed up; the migration verifies model contents unchanged and records an audit. This is verified cache reuse, not a benchmark refit. Unproven cases retain their old signature for ordinary refitting. It does not permit reuse of the untraceable primary configuration.

## Retained files and final verification

`results/archive/` contains historical outputs and is not regenerated. The author-maintained overview SVG is exported by stage 45 to its PDF counterpart, now Figure 1 and the first README image. The submitted tag preserves the original pair. The main manuscript retains three figures: this overview and the replicated and contradictory association figures. Stage 12 requires both overview outputs. The standalone review funnel remains a maintained additional display. The maintained `results/figures/nested_selection_benchmark.png` is regenerated by stage 40 from recorded benchmark repeat metrics. The five-arm benchmark from stage 31 and the current master benchmark display from stage 38 are generated separately under their names above.

The final artifact inventory should be taken only after the pipeline, claim audit, and manuscript compilation finish. Run `python analysis/42_review_artifact_manifest.py`, then `analysis/18_write_manifest.R` again after compilation to refresh manuscript and inventory hashes; the first pipeline manifest can still refer to the previous PDF. The producer inventory covers all files under `results/tables/` and `results/figures/`, plus the generated manuscript tables/macros and PDF, including files whose bytes stayed unchanged. It excludes historical archives and treats hand-edited manuscript/claim sources as inputs. Blank observed command fields mean no matching execution was recorded, not successful execution. Keep individual command statuses, distinguish matching checkpoint reuse from refitting, and preserve the unknown original retrieval dates. These records establish computational traceability; they do not remove retrospective cohort heterogeneity, confounding, or the absence of prospective clinical validation.

The artifact inventory does not claim stable SHA-256 values for itself, its coverage report, the subsequently rewritten run manifest, or the append-only command log. Those rows state the reason explicitly. The final run manifest hashes the inventory and coverage report; stage 12 verifies all manifest entries. The command log is excluded from that fixed hash set because completing a later command appends to it.

`analysis/43_review_pdf_audit.py` checks the compiled PDF against current macros, all priority gene names, captions, and declarations. It uses the available bundled Python 3.12.14 and pypdf 6.10.0; the source/claim audits use system Python 3.14.0. Poppler 26.07.0 renders inspection pages. These tool versions are recorded separately from the R package lock. The PDF audit writes no scientific result and does not replace visual inspection.
